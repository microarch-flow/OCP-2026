# Tiered Memory for LLM Inference — A Modeling Framework for KV-Cache Offload

## 核心结论
这是本组最值得优先阅读的 **容量感知 KV 复用模型**：工作负载的潜在复用率不等于缓存实际可实现的复用率。应联合建模 workload × working set × tier hierarchy，而不是仅比较峰值带宽。模型有 GH200 上的初始 dense-model 验证，**不是任意 MoE/稀疏 attention/内存层级的通用实测结论**。[[Server：Composable Memory Systems/Tiered Memory for LLM Inference- A Modeling Framework for KV-Cache Offload.pdf#page=5|PDF p.5]] [[Server：Composable Memory Systems/Tiered Memory for LLM Inference- A Modeling Framework for KV-Cache Offload.pdf#page=16|PDF p.16]]

## 关键证据
- Roofline 忽略容量，规则式 sizing 忽略 workload dynamics；相同潜在 reuse，在不同容量下可能得到完全不同 TTFT。[[Server：Composable Memory Systems/Tiered Memory for LLM Inference- A Modeling Framework for KV-Cache Offload.pdf#page=3|PDF p.3]] [[Server：Composable Memory Systems/Tiered Memory for LLM Inference- A Modeling Framework for KV-Cache Offload.pdf#page=6|PDF p.6]]
- 令 S 为 tier capacity、W 为 working set、γ 为 workload reuse，讲者给出：random/conservative `γ_eff = γ × min(1,S/W)`；oracle/optimistic `γ_eff = min(γ,S/W)`。这是演讲提出的模型边界，不能未经访问分布假设验证就当作任意策略的严格数学上下界。[[Server：Composable Memory Systems/Tiered Memory for LLM Inference- A Modeling Framework for KV-Cache Offload.pdf#page=7|PDF p.7]]
- 区分跨 session system-prompt 与 intra-session active context：前者 working set 随 arrival rate × retention window 增长；后者近似随 concurrency × context × bytes/token 增长。演讲示例的 40–60% 与 ≥95% reuse 分属这两类，不是所有业务的先验。[[Server：Composable Memory Systems/Tiered Memory for LLM Inference- A Modeling Framework for KV-Cache Offload.pdf#page=8|PDF p.8]]
- 四步：硬件校准 GEMM/attention/communication/memory primitive → 分解 KV populations → 容量门控 reuse → 按 tier 带宽/延迟计算检索代价。[[Server：Composable Memory Systems/Tiered Memory for LLM Inference- A Modeling Framework for KV-Cache Offload.pdf#page=9|PDF p.9]]

## 指标与条件
初始平台：GH200 NVL2，2×H200 共 288GB HBM3e，2×72-core Neoverse V2 3.1GHz，2×512GB LPDDR5x（每组标注384GB/s），CPU–GPU NVLink 标称900GB/s。Llama3.1-70B FP16、TP=2、vLLM+LMCache、ISL/OSL=30K/128、30K prefix、潜在 reuse=100%、3.8 req/s。[[Server：Composable Memory Systems/Tiered Memory for LLM Inference- A Modeling Framework for KV-Cache Offload.pdf#page=10|PDF p.10]]

p.11 验证固定 KV tier 800GB、batch16；hardware TTFT 随 effective reuse 0.1/0.25/0.5/0.75/1.0 分别标为60.10/56.27/39.12/24.38/5.77秒。**该图不是 p99，也不是 decode TPOT。** 模型抓到下降方向，但柱高与实测并非完全重合。[[Server：Composable Memory Systems/Tiered Memory for LLM Inference- A Modeling Framework for KV-Cache Offload.pdf#page=11|PDF p.11]]

p.12 容量扫100–800GB；模型的 reuse 饱和与实际 TTFT 改善阈值并不完全重合，不能把“容量带来阶跃”改写为“模型准确预测每个拐点”。p.13 concurrency 1–64、KV tier800GB，右轴 TTFT 为 **ms 对数轴**，与 p.11 的秒轴不同；高并发下预测和测量亦有明显差异。[[Server：Composable Memory Systems/Tiered Memory for LLM Inference- A Modeling Framework for KV-Cache Offload.pdf#page=12|PDF p.12]] [[Server：Composable Memory Systems/Tiered Memory for LLM Inference- A Modeling Framework for KV-Cache Offload.pdf#page=13|PDF p.13]]

## 图表与架构
已核对 p.7 公式和 p.11–13 全部验证图的横轴、单位、基线与曲线。最重要的不是从图上摘一个加速比，而是：W随并发扩大 → S/W下降 → hit/reuse崩塌 → prefill重算 → TTFT非线性增加。

## 关联与比较

## 不确定性与待验证
缺少原始点、误差统计、cache policy、warm-up、arrival 分布和 admission-control 细节；capacity-bound 使用的 W 与有效复用定义需实现级验证。p.16 明确 MoE、新 KV 优化、多 tier 和多 vendor 验证仍待完成。架构探索应保留预测区间、模型误差和容量阈值敏感性，不输出假精确 p99。
