# UPCI数据驱动配置：HRR编译与三类Firmware Handoff列表

> 阅读范围：已阅读本文件全部可提取文字（13页）。关键页已视觉核对：3, 7；不代表逐页视觉审核。

## 核心结论

- UPCI把开发时HRR与运行时MRR分开，硅能力、板能力和profile经compiler生成binary/ACPI/JSON/schema；目标是减少平台配置硬编码。[[Open Platform Firmware (OPF)/From Code to Data- Advancing the Unified Platform Configuration Interface (UPCI).pdf#page=2|PDF p.2]][[Open Platform Firmware (OPF)/From Code to Data- Advancing the Unified Platform Configuration Interface (UPCI).pdf#page=3|PDF p.3]]
- bFHTL/uFHTL由PEP读取验证并合入rFHTL，Host在后续初始化维护它；持久配置与当前运行交接不能混为同一不可变blob。[[Open Platform Firmware (OPF)/From Code to Data- Advancing the Unified Platform Configuration Interface (UPCI).pdf#page=7|PDF p.7]][[Open Platform Firmware (OPF)/From Code to Data- Advancing the Unified Platform Configuration Interface (UPCI).pdf#page=9|PDF p.9]][[Open Platform Firmware (OPF)/From Code to Data- Advancing the Unified Platform Configuration Interface (UPCI).pdf#page=11|PDF p.11]]

## 关键证据

- HRR支持YAML/JSON、格式与数据定义分离、版本化和required/optional字段。[[Open Platform Firmware (OPF)/From Code to Data- Advancing the Unified Platform Configuration Interface (UPCI).pdf#page=4|PDF p.4]]
- UPCI/openSFI共用拟议XFERLIST_UPCI TE；记录可新增/更新/标空删除，面向ACPI等多段表提供最小逻辑子记录。tag正式分配仍待确认。[[Open Platform Firmware (OPF)/From Code to Data- Advancing the Unified Platform Configuration Interface (UPCI).pdf#page=8|PDF p.8]][[Open Platform Firmware (OPF)/From Code to Data- Advancing the Unified Platform Configuration Interface (UPCI).pdf#page=10|PDF p.10]]
- 行动项仍是finalize HRR/MRR schema和CPU/Memory/PCIe子域结构。[[Open Platform Firmware (OPF)/From Code to Data- Advancing the Unified Platform Configuration Interface (UPCI).pdf#page=12|PDF p.12]]

## 指标与条件

无镜像体积、编译时间、启动时间或移植工时实测。p.8 record type范围均标proposed，不应直接作为冻结ABI实现。[[Open Platform Firmware (OPF)/From Code to Data- Advancing the Unified Platform Configuration Interface (UPCI).pdf#page=8|PDF p.8]]

## 图表与架构

已视觉核对p.3开发流和p.7运行交接流：多个输入汇入compiler；PEP后进入openSFI多阶段并存在reconfigure/reset分支。

## 关联与比较

与openSFI接口契约互补：标准调用若仍依赖私有配置结构无法充分移植；UPCI为配置携带/覆盖/持久化提供数据面。

## 不确定性与待验证

需要定义配置签名/授权、合并优先级、版本兼容与跨重启失败原子性；数据驱动不代表配置无需安全审计。
