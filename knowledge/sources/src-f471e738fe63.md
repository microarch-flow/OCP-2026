# RAS API映射PLDM：错误记录、动作请求与队列语义

> 阅读范围：已阅读本文件全部可提取文字（19页）。关键页已视觉核对：9, 14；不代表逐页视觉审核。

## 核心结论

- DSP2094目标是RAS endpoint/initiator经PLDM互通的informative建模文档，不是新PLDM类型；复用type 2监控控制与type 7文件传输。[[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=5|PDF p.5]]
- CPER承载错误/动作结果，CPAD承载动作请求；接口可同时支持独立的in-band和OOB路径，但队列容量/清除/溢出语义是兼容性关键。[[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=3|PDF p.3]][[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=4|PDF p.4]][[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=11|PDF p.11]][[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=12|PDF p.12]]

## 关键证据

- p.9 PLDM建模范围在MC endpoint与BMC initiator之间，Redfish与分析器是更外层CPER/CPAD范围；分析器也可位于BMC。[[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=9|PDF p.9]]
- 端点可有最多4类错误队列，以及动作与状态队列；CPER queue也可能含多种severity。[[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=4|PDF p.4]][[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=10|PDF p.10]]
- Clear_CPER可选；若不支持，Get_CPER隐式pop。溢出以stressed sensor状态报告，下一条CPER被取走后恢复normal。CPAD队列无空位则请求失败。[[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=11|PDF p.11]][[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=12|PDF p.12]]
- DfWrite和StructuredAttribute等还有对外发布/使用依赖，不能只检查DSP2094文档号。[[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=7|PDF p.7]]

## 指标与条件

最多4个错误队列是结构上限，不是队列深度或无丢失保证。缺事件速率、CPER长度分布、溢出率和故障风暴下BMC处理预算。[[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=4|PDF p.4]][[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=10|PDF p.10]]

## 关联与比较

与bulk telemetry/crash dump区别：RAS API包含可发起动作及其结果闭环，不只是上传诊断文件；CPER读取副作用与重试幂等性影响自动化修复正确性。

## 不确定性与待验证

WIP材料。SerialTxFIFO替代模型尚讨论CPER边界与部分传输，需验证重试、双路径并发读取、记录完整性和先读后删的崩溃窗口。[[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=18|PDF p.18]][[manageability-workshop/OCP RAS API PLDM Modeling.pdf#page=19|PDF p.19]]
