# Securing the Open Chiplet Economy: Defining a Common Security Architecture for FCSA

## 核心结论
FCSA1.1把chiplet安全、boot sequencing和implementation constraints加入共同系统契约。目标是 **可达到与等效monolithic SoC相当的安全性**，不是“多chiplet天然同等安全”或一纸规范即通过产品认证。

## 关键证据
- v1.1新增security chapter、boot interface/rules、implementation requirements；p.15时间线标final release2026-10-12。均为演讲时点状态。[[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=4|PDF p.4]] [[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=15|PDF p.15]]
- 统一boot sequence信号支持distributed/shared/independent NVM拓扑，启动数据来源和系统允许继续的时点分离。[[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=5|PDF p.5]] [[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=6|PDF p.6]]
- independent：各自load完成后secondary Ready、primary Go；shared：先等共享NVM可访问，再load、再次Ready/Go；distributed：primary将代码发给secondary后Go。这些是顺序控制，不替代代码真实性验证。[[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=23|PDF p.23]] [[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=24|PDF p.24]] [[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=25|PDF p.25]]
- security policy取决于risk/trust/market；system RoT汇总各chiplet CRoT-A输入并施加policy。chapter提供system/adversary model、threat/mitigation与可测试要求；minimum profiles和更完整interop实现仍future work。[[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=8|PDF p.8]] [[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=9|PDF p.9]] [[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=10|PDF p.10]] [[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=11|PDF p.11]]
- p.12视觉补读TARA流程：asset/threat/impact/attack feasibility/risk/treatment；另列unresponsive chiplet的DoS、TOCTOU、超额制造等。p.13/14将FCSA安全目标映射到SiP protection-profile的SFR/SAR示例，debug control仍待加入，vertical integration未被当前PP覆盖。**映射模板不等于认证结果。** [[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=12|PDF p.12]] [[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=13|PDF p.13]] [[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=14|PDF p.14]]

## 指标与条件
没有面积、功耗、加密吞吐、boot-time或攻击测试结果。p.7新增memory traffic适配及按系统总需求size snoop filter的implementation要求，说明功能互操作也依赖容量/实现约束，非仅pin兼容。[[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=7|PDF p.7]]

## 图表与架构
已核对boot拓扑和时序、TARA/PP、release timeline及AMBA C2C图。p.18把AXI/CHI放在common packetization层之上、UCIe/BoW transport之上；不是把SCMI管理消息和data-plane coherence混为一个协议。[[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=18|PDF p.18]]

## 关联与比较
[[knowledge/concepts/compute-memory-chiplet-system-contracts|系统契约]]；[[knowledge/concepts/compute-memory-cxl-failure-domain|可观测故障]]。与Caliptra讲座互补：Caliptra是可用RoT技术，FCSA定义跨供应商的系统安全分析和预期行为。

## 不确定性与待验证
v1.2候选包括更多security、functional safety、management processors、time sync、RAS和AMBA C2C alignment；只是under consideration，不应写成1.1已包含。[[Server：Open Chiplet Economy/Securing the Open Chiplet Ecosystem- Defining a Common Security Architecture for FCSA.pdf#page=17|PDF p.17]] 产品还需明确威胁模型、profile、配置、fault handling和合规证据。
