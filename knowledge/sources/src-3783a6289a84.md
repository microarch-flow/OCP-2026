# Co-Designing-AI-Fabrics-Inside-Google-s-Virgo-Network-and-the-Campus-as-a-Computer

## 核心结论
Google 的 Virgo 把 campus 当作计算机，使用独立后端 scale-out 与前端 Jupiter 网络、多 plane 两层交换以及主机/网络联合遥测。目标是性能、可靠性与部署速度共同优化，而非单一交换机峰值。[[ai-clusters/Co-Designing-AI-Fabrics-Inside-Google-s-Virgo-Network-and-the-Campus-as-a-Computer.pdf#page=4|PDF p.4]] [[ai-clusters/Co-Designing-AI-Fabrics-Inside-Google-s-Virgo-Network-and-the-Campus-as-a-Computer.pdf#page=5|PDF p.5]] [[ai-clusters/Co-Designing-AI-Fabrics-Inside-Google-s-Virgo-Network-and-the-Campus-as-a-Computer.pdf#page=6|PDF p.6]]

## 关键证据
- 多 plane 对应 SerDes 级 skinny links，宣称无需第三交换层扩展；单 plane 故障时理论带宽保留 (N-1)/N，前提是 plane 等容量且余下路径可被负载利用。后半句为本知识库对公式适用条件的解释。[[ai-clusters/Co-Designing-AI-Fabrics-Inside-Google-s-Virgo-Network-and-the-Campus-as-a-Computer.pdf#page=7|PDF p.7]]
- packet-level load balancing、交换机自适应路由，以及面向自有主机栈 bare-metal 客户的 SRv6 source routing。[[ai-clusters/Co-Designing-AI-Fabrics-Inside-Google-s-Virgo-Network-and-the-Campus-as-a-Computer.pdf#page=7|PDF p.7]]
- CSIG 向端点回传拥塞；HST 给出亚毫秒交换机可见性；Firefly 提供微秒级 NIC 时钟同步，用于对齐端到端证据。[[ai-clusters/Co-Designing-AI-Fabrics-Inside-Google-s-Virgo-Network-and-the-Campus-as-a-Computer.pdf#page=8|PDF p.8]]

## 指标与条件
两层、N plane、亚毫秒 HST、微秒时钟同步是架构/能力描述，未给请求 p99 或每 GPU 实测吞吐。Falcon 页称低尾延迟、硬件选择性恢复与线速 PSP，但无延迟数值/包长/负载条件。[[ai-clusters/Co-Designing-AI-Fabrics-Inside-Google-s-Virgo-Network-and-the-Campus-as-a-Computer.pdf#page=9|PDF p.9]]

## 图表与架构
已核对 p.6–7：图示 Virgo plane 与 Jupiter/Apollo 路径分开，不能把 Apollo OCS 当成 Virgo 内的 packet switch。双层 fully non-blocking 是作者声明，部署端口与超售表未附。
