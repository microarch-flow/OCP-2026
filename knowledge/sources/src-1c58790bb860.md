# TPM+SPDM+PQC演示：通道保护与密码敏捷分层落地

> 阅读范围：已阅读本文件全部可提取文字（10页）。关键页已视觉核对：7；不代表逐页视觉审核。

## 核心结论

- 演讲从Project Kirkland演进到标准化TPM-over-SPDM：将TPM命令/响应放入认证、加密、完整性保护会话，并结合DICE绑定Host身份和固件测量。[[Security/Future-proof security in TPM with SPDM and PQC capabilities.pdf#page=2|PDF p.2]][[Security/Future-proof security in TPM with SPDM and PQC capabilities.pdf#page=3|PDF p.3]][[Security/Future-proof security in TPM with SPDM and PQC capabilities.pdf#page=4|PDF p.4]]
- PQC能力依赖安全执行基础、密码库、硬件加速与低层固件可升级，不是单选某算法即可future-proof。[[Security/Future-proof security in TPM with SPDM and PQC capabilities.pdf#page=6|PDF p.6]]

## 关键证据

- 展示SLB9678+Raspberry Pi prototype，Linux SPDM、TPM2-TSS/PYTSS加入支持，OpenSSL为3.6.0-dev；内核支持仍标to be released。[[Security/Future-proof security in TPM with SPDM and PQC capabilities.pdf#page=7|PDF p.7]]
- 演讲列TPM规范1.85、PTP1.07和EK Profile2.7路径，图有代际pin兼容主张，但没有完整SKU兼容/迁移验证表。[[Security/Future-proof security in TPM with SPDM and PQC capabilities.pdf#page=5|PDF p.5]]

## 指标与条件

无ML-DSA/ML-KEM操作延迟、吞吐、TPM总线带宽或PQC内存需求；p.7 CC EAL6+标签指IFX PQC crypto library，不能扩大为整套demo或系统认证。[[Security/Future-proof security in TPM with SPDM and PQC capabilities.pdf#page=7|PDF p.7]]

## 图表与架构

已视觉核对p.7软硬件层次及认证标签所属，确认是演示栈而非所有软件已上游发布。

## 关联与比较

与TCG概述互补：前者给标准组件，这里给供应商实现PoC；厂商原型和规范发布仍不同于跨厂商部署可用。

## 不确定性与待验证

需查正式产品/固件/上游版本、认证范围及主动interposer威胁测试；没有性能结果则不能推断PQC开销可忽略。
