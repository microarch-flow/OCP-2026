# 01_AI Cluster Benchmarks – Establishing a standardized evaluation system 

## 核心结论
Huawei介绍AISBench（AI训练/推理）与ClusterBench（通用superpod）的L0硬件→L1系统→L2业务分层。可取之处是把资源容量、通信效率、业务QoS和可靠性分开，不把峰值算力当有效吞吐。[[ai-clusters/01_AI Cluster Benchmarks – Establishing a standardized evaluation system .pdf#page=2|PDF p.2]] [[ai-clusters/01_AI Cluster Benchmarks – Establishing a standardized evaluation system .pdf#page=5|PDF p.5]] [[ai-clusters/01_AI Cluster Benchmarks – Establishing a standardized evaluation system .pdf#page=9|PDF p.9]]

## 关键证据
AISBench解耦dataset/inference/evaluation，支持质量、latency/throughput以及vLLM speculative decoding counters。Acceptance rate=accepted/draft tokens；acceptance length=1+accepted/drafts，是不同口径，不能混用。[[ai-clusters/01_AI Cluster Benchmarks – Establishing a standardized evaluation system .pdf#page=3|PDF p.3]] [[ai-clusters/01_AI Cluster Benchmarks – Establishing a standardized evaluation system .pdf#page=4|PDF p.4]] [[ai-clusters/01_AI Cluster Benchmarks – Establishing a standardized evaluation system .pdf#page=8|PDF p.8]]
ClusterBench用trough/burst/peak阶段测低负载latency、高负载吞吐及QoS-compliant throughput，并覆盖VM/container与资源超配。[[ai-clusters/01_AI Cluster Benchmarks – Establishing a standardized evaluation system .pdf#page=10|PDF p.10]] [[ai-clusters/01_AI Cluster Benchmarks – Establishing a standardized evaluation system .pdf#page=12|PDF p.12]]

## 指标与条件
p.6 full-stage QPM397 vs stable420约6%差异是**统计窗口变化**，不是硬件/算法加速；支持250K requests指总请求量，不是250K并发。p.16 Redis示例称1.33×内存超配带来23% throughput gain；Openclaw100个2U4G VM、CPU超配2.08，memory超配1.25→2.5时平均网页latency17.9→28.3s，task success均100%。平均latency显著增长，不能仅凭成功率称SLA无损。[[ai-clusters/01_AI Cluster Benchmarks – Establishing a standardized evaluation system .pdf#page=6|PDF p.6]] [[ai-clusters/01_AI Cluster Benchmarks – Establishing a standardized evaluation system .pdf#page=16|PDF p.16]]
