# Near Data Processing Opportunities for Context Engineering

## 核心结论
只建模 prefill/decode 会漏掉 context retrieval、整理、更新和前处理。材料提出 context→prefill→decode 的第三支柱视角；近数据机会由“大数据量 + 局部不规则访问 + 低算术强度”识别，而不只是看到 RAG 就决定卸载。[[fti-workshop-data-centric-computing/Near-Data-Processing-opportunities-for-context-engineering.pdf#page=4|PDF p.4]] [[fti-workshop-data-centric-computing/Near-Data-Processing-opportunities-for-context-engineering.pdf#page=6|PDF p.6]] [[fti-workshop-data-centric-computing/Near-Data-Processing-opportunities-for-context-engineering.pdf#page=9|PDF p.9]]

## 关键证据
- context 不只有文本：token-level、参数内记忆、latent representation（embedding/KV 等）；生命周期包括 consolidate/update/forget/retrieve/prompt，评价需包含质量、新鲜度、provenance、latency、token budget。[[fti-workshop-data-centric-computing/Near-Data-Processing-opportunities-for-context-engineering.pdf#page=3|PDF p.3]] [[fti-workshop-data-centric-computing/Near-Data-Processing-opportunities-for-context-engineering.pdf#page=4|PDF p.4]]
- 作者实验认为 context work 往往 memory/I/O-bound，在 dense prefill 前形成另一段低算术强度阶段。这是特定工作负载观察，非所有 context 操作的定律。[[fti-workshop-data-centric-computing/Near-Data-Processing-opportunities-for-context-engineering.pdf#page=6|PDF p.6]]
- 软件“bowtie”：很多可卸载操作对接很多 PIM/PNM/CSD/XPU，需要中间表达与运行时，单一垂直栈不能证明任意硬件可移植。[[fti-workshop-data-centric-computing/Near-Data-Processing-opportunities-for-context-engineering.pdf#page=10|PDF p.10]]

## 指标与条件
p.7 为 Llama3.1 405B 的 RAG profiling，对比 small vectorDB 4G 与 large vectorDB 1.2TB，画 avg/p50/p90/p99 分项。作者称部分情形 RAG 接近总时间 30%；未披露完整机器、query/context/output 长度、命中率。尤其 **分项 p99 不能直接相加推导端到端 p99**，不将该堆叠图当严格尾延迟归因。[[fti-workshop-data-centric-computing/Near-Data-Processing-opportunities-for-context-engineering.pdf#page=7|PDF p.7]]
p.8 引用外部 LanceDB/S3 案例是规模动机，不是作者同一实验，更不是近数据硬件 speedup。[[fti-workshop-data-centric-computing/Near-Data-Processing-opportunities-for-context-engineering.pdf#page=8|PDF p.8]]

## 图表与架构
p.5 传统 PD 图中的 orchestrator 只做协调；p.6 将 context work 放在 prefill 之前。真实服务中这些阶段可能重叠或反馈循环，建模时需测 critical path，不能机械相加所有耗时。[[fti-workshop-data-centric-computing/Near-Data-Processing-opportunities-for-context-engineering.pdf#page=5|PDF p.5]] [[fti-workshop-data-centric-computing/Near-Data-Processing-opportunities-for-context-engineering.pdf#page=6|PDF p.6]]

## 关联与比较
[[knowledge/concepts/compute-memory-ndp-contract|近数据卸载契约]] 的 workload 筛选入口。与共享池 tokenization 复用互证：当 KV/prefill 复用有效，前处理占比会上升，但应先 profile 而非假设固定 30%。

## 不确定性与待验证
尚未对比具体近数据实现的系统性能、质量或功耗。下一步应测 context p50/p99、检索 recall、query bytes/result bytes、CPU排队和 cache hit，而不是只收集 GEMV 峰值。
