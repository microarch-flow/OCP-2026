# DC-MHS: Datacenter-Secure Control Module (DC-SCM) 3.0 Specification Update

## 核心结论
DC-SCM3.0 试图减少 SCM–HPM co-design 依赖，区分 direct/indirect management，并以更少、更单一功能 pin 与按需生成远端总线提高复用。它不是2.2可直接替换的升级卡。[[server/03_MHS Datacenter-Secure Control Module (DC-SCM) 3.0 Specification Update.pdf#page=2|PDF p.2]] [[server/03_MHS Datacenter-Secure Control Module (DC-SCM) 3.0 Specification Update.pdf#page=3|PDF p.3]] [[server/03_MHS Datacenter-Secure Control Module (DC-SCM) 3.0 Specification Update.pdf#page=5|PDF p.5]]

## 关键证据
- 演讲状态：2.2 广泛使用且不计划继续增强；3.0 约17家公司参与，目标0.5包2026年底、1.0在2027大会、首批产品可能2028。皆为快照/计划，不当已完成发布。[[server/03_MHS Datacenter-Secure Control Module (DC-SCM) 3.0 Specification Update.pdf#page=2|PDF p.2]]
- form factor/pinout **前后均不兼容**，需双向防误插。section0 mini-SCI、section1 typical、section2 maximum 支持不同配置；确切 connector 尚TBD。[[server/03_MHS Datacenter-Secure Control Module (DC-SCM) 3.0 Specification Update.pdf#page=2|PDF p.2]] [[server/03_MHS Datacenter-Secure Control Module (DC-SCM) 3.0 Specification Update.pdf#page=3|PDF p.3]]
- USB bridging 取代许多直接总线；critical bits 仍需实时、始终可用接口。LTPI 保留1.0、升级2.0加link/random access、或废弃三种方向尚征求意见。[[server/03_MHS Datacenter-Secure Control Module (DC-SCM) 3.0 Specification Update.pdf#page=5|PDF p.5]]

## 指标与条件
p.6 标 **Tentative—not comprehensive**。其中host PCIe由2.2的x1/x1/x4转向mini-SCI x1；I3C/I2C直接引脚减少、按需桥接。不能把整张表当冻结 pinout。[[server/03_MHS Datacenter-Secure Control Module (DC-SCM) 3.0 Specification Update.pdf#page=6|PDF p.6]]

## 图表与架构
p.4 direct/indirect、interposer、多host组合并列，双host真实需求还带问号。HFF/CFF继续考虑，mini-SCI M.2、液冷、显示接口变更仍在评估，2U vertical不再继续工作。[[server/03_MHS Datacenter-Secure Control Module (DC-SCM) 3.0 Specification Update.pdf#page=4|PDF p.4]] [[server/03_MHS Datacenter-Secure Control Module (DC-SCM) 3.0 Specification Update.pdf#page=7|PDF p.7]]

## 关联与比较
[[knowledge/concepts/compute-memory-modular-platform-contract|模块化平台契约]]：减少physical pins把复杂度移向bridge、协议、发现和错误恢复；不能用“更少连接器”代表总复杂度必降。

## 不确定性与待验证
多节点管理隔离、USB桥接失效域、关键bit实时性、LTPI路线和最终机械keying尚未定。本文不提供生产接线/兼容性保证。
