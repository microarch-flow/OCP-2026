# Google Project Equilibrium：威胁模型驱动的持续安全扫描

## 核心结论
核心架构是与编码agent分离的presubmit安全agent：威胁模型→上下文/调用图→初筛/triage→补丁agent，再加夜间回归。重点从一次全库扫描的告警量转向可被工程师吸收的闭环，不是宣称自动扫描能替代安全责任。[[expo-hall-sessions/04_From Fleet to Firmware Bringing AI-Native Security to Open Hardware wi.pdf#page=4|PDF p.4]] [[expo-hall-sessions/04_From Fleet to Firmware Bringing AI-Native Security to Open Hardware wi.pdf#page=5|PDF p.5]] [[expo-hall-sessions/04_From Fleet to Firmware Bringing AI-Native Security to Open Hardware wi.pdf#page=12|PDF p.12]]

## 关键证据、指标与条件
- 自述约1250个已修复bug，部分接入阶段平均每月预防196漏洞；前者累计时间未给，不能两数相除估计周期。p8图是每日CL扫描及有finding的CL数量，25K累计扫描、100+威胁模型，不是漏洞召回曲线。[[expo-hall-sessions/04_From Fleet to Firmware Bringing AI-Native Security to Open Hardware wi.pdf#page=7|PDF p.7]] [[expo-hall-sessions/04_From Fleet to Firmware Bringing AI-Native Security to Open Hardware wi.pdf#page=8|PDF p.8]]
- triage的355-CL基准：precision91.1%、recall77.2%、F1 83.6%。因此“近零误报”是营销表达，不是precision=100%；召回仍遗漏约22.8%的基准正例，且不能外推全生产漏洞分布。[[expo-hall-sessions/04_From Fleet to Firmware Bringing AI-Native Security to Open Hardware wi.pdf#page=10|PDF p.10]]
- 5.8s/bug、约100s/CL、10worker并发下10.3bugs/min；页面同时提单worker预处理优化，未说明指标是否同一并发和分母。**平均100s不证明p99<5min**。[[expo-hall-sessions/04_From Fleet to Firmware Bringing AI-Native Security to Open Hardware wi.pdf#page=10|PDF p.10]]
- BugFixAgent本地CLI成功率78.4%；90%+是加入自审及离线改进的目标，不是当前结果，也未给成功的验证定义/样本数。[[expo-hall-sessions/04_From Fleet to Firmware Bringing AI-Native Security to Open Hardware wi.pdf#page=11|PDF p.11]]

## 图表与架构
已核p7/8/10。安全上下文采用即时AST、本地目录、团队CL模式及Kythe混合调用图；依赖B的验证逻辑变化会触发A的安全基线升级，这是固件供应链依赖传播，而不仅关键词扫描。[[expo-hall-sessions/04_From Fleet to Firmware Bringing AI-Native Security to Open Hardware wi.pdf#page=9|PDF p.9]] [[expo-hall-sessions/04_From Fleet to Firmware Bringing AI-Native Security to Open Hardware wi.pdf#page=10|PDF p.10]]
