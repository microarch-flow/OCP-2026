# Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC

## 核心结论
MRC 试图在保留可靠连接、有序完成及 QP/CQ 软件抽象的条件下，把包级多路径、多 plane、选择性重传和失效路径规避下沉到传输层；乱序不外泄成应用完成乱序。[[ai-clusters/Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC.pdf#page=3|PDF p.3]] [[ai-clusters/Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC.pdf#page=5|PDF p.5]]

## 关键证据
- 对比 RC 的单 QP ECMP 固定路径、go-back-N、依赖超时与路由收敛，MRC 将 route/Entropy Value 排除变成端点路径选择动作。SRv6 不是“让路由协议更快”，而是解除端点对其收敛的依赖。[[ai-clusters/Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC.pdf#page=4|PDF p.4]] [[ai-clusters/Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC.pdf#page=6|PDF p.6]]
- responder 通告 MPR，限制发送端重传追踪和接收端乱序状态；图中 MPR=8 packets **仅为示意**，不代表产品默认值。[[ai-clusters/Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC.pdf#page=7|PDF p.7]]
- SACK/NACK 为可靠性反馈；packet trimming、probe 为可选加速。不能把所有可选功能当作所有 NIC 必备。[[ai-clusters/Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC.pdf#page=8|PDF p.8]]
- 规范规定 ECN、delivery accounting、RTT、responder backpressure、reflected EV 等反馈；NSCC 是所展示实现使用的 sender/window/SACK-clocked 策略，不是唯一强制 CC。[[ai-clusters/Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC.pdf#page=9|PDF p.9]]
- 应用 mrc.h 与 CAP_NET_ADMIN 控制器 mrc_ctl.h 分离；EV/CC policy 可跨 QP 共享；连接建立仍 out-of-band。[[ai-clusters/Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC.pdf#page=11|PDF p.11]]

## 指标与条件
p.12 描述生产训练任务 75K GPUs，T1 停转影响约 25% QP、约 580K 包丢失；p.13 为该类故障期间真实训练吞吐/丢包曲线。已核对双纵轴：吞吐单位 Pb/s，丢包率单位 percent，横轴是相对 reboot 的分钟，**不是微秒恢复测量**。未给出请求 p99、重复试验次数、工作负载模型、每 GPU NIC 配置与总恢复时延统计。[[ai-clusters/Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC.pdf#page=12|PDF p.12]] [[ai-clusters/Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC.pdf#page=13|PDF p.13]]

## 图表与架构
已核对 p.7 的 PSN window 与 p.13 故障/reboot/up 标线。可支持“故障后训练吞吐短暂下降并恢复”的作者演示结论，不足以量化毫秒级 failover 或保证所有流无感。

## 不确定性与待验证
10⁶ nodes 是设计方向而非此实验规模。[[ai-clusters/Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC.pdf#page=2|PDF p.2]] 需要 NIC 资源/MPR/BDP、队列公平性、故障下 p99、拥塞控制互操作及控制器失效策略，才可用于推理部署决策。p.12 页脚有“Cisco Confidential”字样；这里只分析用户仓库提供资料，不将其等同为公开规范。[[ai-clusters/Enabling-AI-Networking-Scale-with-Multi-path-Reliable-Connections-MRC.pdf#page=14|PDF p.14]]
