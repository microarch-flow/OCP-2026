# Agentic AI Serving System with Computational Shared Memory Pool

## 核心结论
共享池的价值分三层：提前释放 prefill HBM；在池内保存完整 KV、只为 decode 选择少量 KV；复用 token IDs 避免长前缀重复 tokenization。内存分配的 pooling 不自动等于跨服务共享数据的 sharing。[[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=3|PDF p.3]] [[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=8|PDF p.8]] [[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=12|PDF p.12]] [[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=22|PDF p.22]]

## 关键证据
- MARS 图中机架内连接是 CXL，计算机架与内存机架间是 RDMA；不能概括为全系统跨机架 CXL。[[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=4|PDF p.4]]
- 池可在 decode GPU 满载时接走 prefill KV，解除 prefill HBM 被待交付请求占住的问题；瓶颈可能转移到池容量、链路和队列。[[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=8|PDF p.8]]
- RocketKV Stage 1/SnapKV-style selection 在池侧执行。完整 KV 留池供后续轮次重新选择，区别于不可逆永久删除；图称平均约 30× 的 KV reduction，不是所有任务等质量压缩比。[[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=12|PDF p.12]] [[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=13|PDF p.13]]
- 按层流水：layer L 的 KV + last query block 传输和评分，与 layer L+1 prefill 重叠；decode 按索引取被选部分。[[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=17|PDF p.17]]

## 指标与条件
- p.10 宣称相对 LMCache 1.67× TTFT、相对全部重算的 NIXL 1.9× peak goodput。图给 SLO=400 ms，横轴 concurrency，throughput 与 goodput 分开；未列完整模型、GPU、prompt 分布，不能外推为通用 p99 改善。[[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=10|PDF p.10]]
- p.18 是 **mean latency**（ms），不是 p99：[[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=18|PDF p.18]]

**原页不一致**：headline 写 Arcee TTFT 1.4×、E2E 2.29× vs Mooncake。E2E 与柱值吻合；TTFT 按柱值为 709.47/398.45≈1.78×，不能静默替作者修成同一个结果。保留两者待查。
- 25.6K input、96% prefix KV reuse：移除 tokenization 的理想消融为 TTFT≈345→215 ms；实际 token sharing 是 tokenization≈130→6 ms、TTFT≈345→221 ms。不能把 oracle 结果当实现结果。[[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=20|PDF p.20]] [[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=23|PDF p.23]]

## 图表与架构
CMM-Ax 3.0 图为 CXL 2.0 Type3/PCIe5×16、512 GB DDR5、200 GB/s 本地内存、16 Neoverse V2@3 GHz；命令队列与数据路径分别进入设备 runtime。[[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=16|PDF p.16]] token-sharing 图仍发送 full prompt、返回 full token IDs，只省重复计算，非消除 prompt 传输。[[fti-workshop-data-centric-computing/Agentic-AI-Serving-System-with-Computational-Shared-Memory-Pool.pdf#page=22|PDF p.22]]

## 关联与比较
[[knowledge/concepts/compute-memory-kv-placement|KV 放置]] 与 [[knowledge/concepts/compute-memory-capacity-vs-datapath|收益归因]]：本篇又加入算法选择和 CPU 前处理复用，不能把总体收益全部归于 CXL 链路。高 prefix reuse 降低 prefill 后，tokenizer 更可能成为 TTFT 占比显著的部分。

## 不确定性与待验证
缺少 selection 的质量/召回对照、模型配置、tokenizer 边界重分词与版本一致性、共享对象隔离以及池故障恢复。p.21 图像 tokenization 移除实验只是潜力上界，不证明实际图像 offload 已达到同等效果。
