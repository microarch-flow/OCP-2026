# Datacenter NVMe SSD 测试计划：覆盖、模式与认证边界

> 阅读范围：已阅读本文件全部可提取文字（31页）。未完成图表视觉核对；不把文字提取视作图形关系验证。

## 核心结论

这份多厂商材料展示测试计划的迭代与工具实现，并不构成统一 OCP 认证证书。最容易误用的地方是把测试数量当覆盖率、把加速工厂模式当最终 qualification、把工具厂认证标识当 OCP 官方认可。[[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=4|PDF p.4]][[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=13|PDF p.13]][[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=18|PDF p.18]][[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=20|PDF p.20]]

## 关键证据

- Microsoft 部分把预处理、并行依赖分组、随机稳态生成等列为缩短测试时间的工作，并计划贡献全面测试计划。[[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=5|PDF p.5]]
- 错误注入从 panic 分类转向 event 分类；DSSD 2.7 中 Error Injection/Panic ID 改名，恢复行为和新事件持续扩展。测试规范会变化，必须固定版本。[[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=6|PDF p.6]][[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=8|PDF p.8]][[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=9|PDF p.9]]
- SANBlaze 明确说明该工作不是 OCP 官方 sanction/certification program，并提出建立正式认证计划的建议。[[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=13|PDF p.13]][[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=20|PDF p.20]]

## 指标与条件

DSSD 2.5 对应 183 tests（新增 48），2.6 对应 191（新增 8）；2.7 gap analysis 完成、计划开发约 6–10 个新测试，是演讲时点的计划状态，不能合并成“所有设备均通过”。原始 10 类 panic 与 14 个 test cases 计数口径不同，PLP 模式会增加用例。[[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=4|PDF p.4]][[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=6|PDF p.6]]

工具可容纳 4/16/48 个 SSD 等是不同平台配置，不是已验证并发吞吐；材料没有给出测试套件端到端运行时间对照。[[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=13|PDF p.13]][[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=24|PDF p.24]]

## 关联与比较

Factory Mode 可跳过预处理，ADP Override 可绕过参数检查；最终 qualification 要关闭 override。测试环境本身必须纳入结果记录，与 CTAM/CPACT 一样，工具执行不等于符合性证明。[[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=18|PDF p.18]]

## 不确定性与待验证

需确认具体套件 commit、DSSD 规范版本、驱动固件、预处理和稳态条件、覆盖矩阵、失败判据以及复测策略。厂商列出的 CDL/UNH 等资质需要逐项目核验，不能外推所有产品或整个平台。[[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=16|PDF p.16]][[storage/Comprehensive-Testing-for-OCP-Datacenter-NVMe-SSD-Specification-Compliance.pdf#page=18|PDF p.18]]
