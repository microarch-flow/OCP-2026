# Open Object Formats for Near Data Processing (and More!)

## 核心结论
本 PDF 主要内容是手绘图片，**已逐页视觉阅读全部 29 页**，而非把极少 native text 当作全文。核心提案是稳定可计算的内存对象格式 + 跨地址空间的 invariant pointer + 可控制局部性的共享模型，减少序列化、重复构建对象和页映射开销。不是只“采用 Arrow”就自动实现零成本共享。[[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=3|PDF p.3]] [[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=5|PDF p.5]] [[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=7|PDF p.7]]

## 关键证据
- 应用/领域库处理向量、图、HNSW 等对象；libmemobj 提供分配、回收和引用解析，kernel 参与尽量少。领域语义可通过显式对象、数据结构或 allocation hints 影响放置。[[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=7|PDF p.7]] [[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=9|PDF p.9]]
- self-contained/invariant references 让对象移动后引用仍可解析；缓存解析结果、指针压缩是降低访问成本的手段，不意味着解析免费。[[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=8|PDF p.8]]
- 附录 p.24 的 64-bit reference 包含 FOT entry 与 offset，FOT 指向 object ID/flags；p.25 对照较大的 fat pointer。共享对象仍需权限映射，p.29 区分虚拟请求权限、logical object permissions 和 DRAM/NVM physical backing。[[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=24|PDF p.24]] [[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=25|PDF p.25]] [[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=29|PDF p.29]]
- append/immutability 被强调为安全、低协调共享的语义基础；对可变对象仍需明确发布、并发修改和生命周期规则。[[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=23|PDF p.23]]

## 图表与架构
“少 page faults”不是“所有访问更快”。p.11/12 给不同示意数量级，p.22 的 warm/cold setup 分解进一步表明载入/构建与计算阶段应分别计时。p.20 对比 runtime 层叠与更直接的 OS/runtime/driver 接入。[[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=11|PDF p.11]] [[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=12|PDF p.12]] [[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=20|PDF p.20]] [[fti-workshop-data-centric-computing/Open-Object-Formats-for-Near-Data-Processing.pdf#page=22|PDF p.22]]

## 关联与比较
[[knowledge/concepts/compute-memory-ndp-contract|近数据卸载契约]]：数据地址表示与可共享语义是函数 API 之前的条件。[[knowledge/concepts/compute-memory-partitioning-placement-ir|分区与放置 IR]]：object hints 和不可变性是 placement 决策可使用的语义，不应只保留裸指针。

## 不确定性与待验证
这是方案/研究结果展示，不是完整对象 ABI 标准。未给跨 ISA endian/layout、撤销权限、对象回收竞态、故障恢复和大规模 coherence 开销的完整规范。p.22 右侧截图本身裁切，未猜补缺失文字。p.17–19 为模板/备份分隔页。
