# Credo 增强光模块遥测：远端分段诊断与持久事件证据

## 核心结论
关键进步不是多一个健康分数，而是从交换机同时看到 local/remote × host/media 四个故障域，并保留故障前后的事件；这能减少裸金属 GPU 服务器侧不可访问造成的盲查。[[networking/05_More Signal, Less Noise Improving AI Cluster Returns Through Standardi.pdf#page=4|PDF p.4]][[networking/05_More Signal, Less Noise Improving AI Cluster Returns Through Standardi.pdf#page=7|PDF p.7]][[networking/05_More Signal, Less Noise Improving AI Cluster Returns Through Standardi.pdf#page=8|PDF p.8]]

## 关键证据、指标与条件
- CMIS CDB 上的共同软件接口覆盖遥测、健康分数、事件日志、远端 CMIS 与固件管理。任务态持续监视、非易失事件日志是不同能力，采购时需分别验收。[[networking/05_More Signal, Less Noise Improving AI Cluster Returns Through Standardi.pdf#page=4|PDF p.4]][[networking/05_More Signal, Less Noise Improving AI Cluster Returns Through Standardi.pdf#page=9|PDF p.9]]
- 试验为 16 个交换端口 400G DR4、16 台服务器 2×200G DR2，共 48 模块，不是规模化生产故障率调查。[[networking/05_More Signal, Less Noise Improving AI Cluster Returns Through Standardi.pdf#page=10|PDF p.10]]
- 启动检查定位远端 host 电眼异常：health 40、三个 eye-height 值 26/29/31，pre-FEC BER 1.5×10^-6；media 端健康。清理/重插后恢复，但这个联合干预不能区分清洁与重插各自的因果贡献。[[networking/05_More Signal, Less Noise Improving AI Cluster Returns Through Standardi.pdf#page=11|PDF p.11]]
- 0/5/10dB 衰减对应总体 good/warning/critical 的示例为 80/60/40；实际 5dB 组已有 80、60、40 混合，10dB 组有一条 link down。不是确定的“每 5dB 恰好扣 20 分”公式。[[networking/05_More Signal, Less Noise Improving AI Cluster Returns Through Standardi.pdf#page=14|PDF p.14]][[networking/05_More Signal, Less Noise Improving AI Cluster Returns Through Standardi.pdf#page=15|PDF p.15]]

## 图表与架构
已核 p.11 四域表和 p.14/15 衰减表/摘要。远端断链行出现 -40 接收功率且身份缺失，不能把这当正常光功率测量；采样时间也不同步，事件关联必须附时间不确定度。[[networking/05_More Signal, Less Noise Improving AI Cluster Returns Through Standardi.pdf#page=14|PDF p.14]]

## 关联与比较
[[knowledge/concepts/network-optics-reliability]]、[[knowledge/concepts/network-clock-evidence]]：最差项分数用于筛查，原始 metrics、事件、身份与时钟证据用于定责；分数不可替代底层数据或误报统计。

## 不确定性与待验证
未给跨厂商分数标定、误报/漏报、采集开销、MTTR 前后对照；“数分钟扫描整个 fabric”没有设备规模/轮询并发条件。远端固件管理还需鉴权、失败回滚与带外恢复验证，不能直接把可遥测等同可安全自动修复。
