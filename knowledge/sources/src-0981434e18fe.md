# System GPU Management：公开profile、事件与聚合模型的接口收敛

> 阅读范围：已阅读本文件全部可提取文字（10页）。未完成图表视觉核对；不把文字提取视作图形关系验证。

## 核心结论

- 公开System GPU工作流继承半私有Hyperscale GPU公开贡献，并通过normative lens找歧义；目标演进一份规范，不维护竞争平行版本。[[systems-management/System-Level-Manageability-for-GPU-Platforms-Progress-in-the-OCP-System-GPU-Management-Workstream.pdf#page=3|PDF p.3]][[systems-management/System-Level-Manageability-for-GPU-Platforms-Progress-in-the-OCP-System-GPU-Management-Workstream.pdf#page=4|PDF p.4]]
- 重点是UBB profile、GPU/fabric事件语义、Redfish资源层级一致性与FRU迁移，属于系统集成契约而非GPU微架构规范。[[systems-management/System-Level-Manageability-for-GPU-Platforms-Progress-in-the-OCP-System-GPU-Management-Workstream.pdf#page=5|PDF p.5]][[systems-management/System-Level-Manageability-for-GPU-Platforms-Progress-in-the-OCP-System-GPU-Management-Workstream.pdf#page=6|PDF p.6]][[systems-management/System-Level-Manageability-for-GPU-Platforms-Progress-in-the-OCP-System-GPU-Management-Workstream.pdf#page=7|PDF p.7]][[systems-management/System-Level-Manageability-for-GPU-Platforms-Progress-in-the-OCP-System-GPU-Management-Workstream.pdf#page=8|PDF p.8]]

## 关键证据

- UBB profile v2.0采用MultipartHttpPushUri；事件用AcceleratorDevice而非NetworkDevice语义，优先扩展Fabrics registry并按Critical/Warning/OK组织。[[systems-management/System-Level-Manageability-for-GPU-Platforms-Progress-in-the-OCP-System-GPU-Management-Workstream.pdf#page=5|PDF p.5]][[systems-management/System-Level-Manageability-for-GPU-Platforms-Progress-in-the-OCP-System-GPU-Management-Workstream.pdf#page=6|PDF p.6]]
- DSP2090提供GPU系统/compute expansion建模指导，避免客户端为不同resource hierarchy写特例。[[systems-management/System-Level-Manageability-for-GPU-Platforms-Progress-in-the-OCP-System-GPU-Management-Workstream.pdf#page=7|PDF p.7]]
- FRU方向让IPMI与DMTF记录共存并从IPMB迁PLDM Type4，作为旧格式日期限制的兼容桥。[[systems-management/System-Level-Manageability-for-GPU-Platforms-Progress-in-the-OCP-System-GPU-Management-Workstream.pdf#page=8|PDF p.8]]
