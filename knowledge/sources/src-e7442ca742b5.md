# Runtime SBOM：把既有SBOM准确关联到active/staged/recovery镜像

> 阅读范围：已阅读本文件全部可提取文字（10页）。关键页已视觉核对：7；不代表逐页视觉审核。

## 核心结论

- Runtime SBOM不是从正在运行的软件重新生成SBOM，而是明确每个组件的installed/staged/recovery/active固件对应哪个构建SBOM。[[systems-management/Runtime-SBOMs-Extending-DMTF-Redfish-to-Connect-Build-Time-and-Live-Software-State.pdf#page=6|PDF p.6]]
- 版本号不足以唯一定位：重构建不改版本、不同配置和厂商标识格式都会歧义；需要artifact身份、状态、provenance和measurement关联。[[systems-management/Runtime-SBOMs-Extending-DMTF-Redfish-to-Connect-Build-Time-and-Live-Software-State.pdf#page=5|PDF p.5]][[systems-management/Runtime-SBOMs-Extending-DMTF-Redfish-to-Connect-Build-Time-and-Live-Software-State.pdf#page=8|PDF p.8]]

## 关键证据

- SoftwareInventory/RelatedItem可表示报告的库存，ComponentIntegrity/SPDM提供测量真实性辅助；attestation既不生成SBOM，也不决定CVE是否适用。[[systems-management/Runtime-SBOMs-Extending-DMTF-Redfish-to-Connect-Build-Time-and-Live-Software-State.pdf#page=8|PDF p.8]]
- 示例处理链包括association、SBOM/CVE/VEX/policy enrichment、fleet findings，强调missing coverage显式呈现和resolve once复用。作者明确此图只说明可能工作方式，不是正式架构提案。[[systems-management/Runtime-SBOMs-Extending-DMTF-Redfish-to-Connect-Build-Time-and-Live-Software-State.pdf#page=7|PDF p.7]]
- 行动项是与OCP/DMTF约定最小association record。[[systems-management/Runtime-SBOMs-Extending-DMTF-Redfish-to-Connect-Build-Time-and-Live-Software-State.pdf#page=9|PDF p.9]]

## 指标与条件

BMC例约500 components/300 third-party/200 upstream projects/25,000+ files是illustrative rounded figures，不是所有BMC基线；不据此计算普遍暴露面。[[systems-management/Runtime-SBOMs-Extending-DMTF-Redfish-to-Connect-Build-Time-and-Live-Software-State.pdf#page=4|PDF p.4]]
