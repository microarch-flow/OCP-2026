# d-Matrix Push Mode与异构推理：统一传输抽象不消除分解代价

## 核心结论
该方案把chiplet/封装/卡/节点的通信组织为统一Push Mode，并以JetStream承载PCIe语义跨Ethernet；异构拆分不仅有prefill/decode，还可分draft/verify和attention/FFN。核心问题是：算力/带宽匹配节省是否大于新增逐层往返、负载失衡和状态迁移代价。[[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=5|PDF p.5]] [[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=7|PDF p.7]] [[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=16|PDF p.16]]

## 关键证据、指标与条件
- Corsair卡标8个6nm chiplet、2GB SRAM/150TB/s、256GB LPDDR5/400GB/s、PCIe128GB/s、DMX Bridge512GB/s、600W TDP。2400/9600“TFLOPS”分别标MXINT8/MXINT4，保留厂商命名，不与不同精度浮点算力直接排名。sub-ms latency未定义模型、消息或分位数。[[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=4|PDF p.4]]
- JetStream列400Gbps Ethernet、PCIe5、150W TDP及2µs latency，未定义测量边界；架构图实际画两路200Gbps EMAC、TLP地址表及打包/解包。相对RoCEv2更低graph-to-graph latency仅有主张，无对照测量。[[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=6|PDF p.6]] [[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=7|PDF p.7]]
- AFD演示页明确GPT-OSS-20B、1×H100+8×Corsair、batch1、一token24次roundtrip；同页给845tokens/s/user及64并发总20,145tokens/s。后者除64约314.8tokens/s/user，不能把845乘64当总吞吐，页面未说明两组是否不同工作点。没有TTFT、长度、量化、p99、墙插功率或原始轨迹。[[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=17|PDF p.17]]
- 16 racks/1024 Corsair Squadron称Arizona研发中心可用，不等于已证实大规模客户生产运行。[[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=9|PDF p.9]]

已核p4/5/7及p10–14、16/17、19–22。p10为leaf-spine下expert与attention分配；p11另一方案为四rail交换机，节点内TP/PP/EP、节点间PP/EP，Push Mode跨rail，不能把两图当同一拓扑性能结果。[[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=10|PDF p.10]] [[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=11|PDF p.11]]

p12把attention概括为任意batch带宽受限，p14又把large-context attention放入compute-bound侧，说明分类是工作负载模型而非普适定律；p13相对GPU的彩条无标尺，只能视为定位。[[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=12|PDF p.12]] [[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=13|PDF p.13]] [[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=14|PDF p.14]]

Raptor以垂直logic+DRAM提高容量：图示单chiplet4GB/12.5TB/s、8chiplet卡32GB/100TB/s、72卡rack约2.3TB/7.2PB/s。这是后续架构描述，不是当前Corsair实测；“16MB backing memory for all 2048 tensor engines”的单位作用域有歧义，不自行推导每引擎容量。[[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=20|PDF p.20]] 3D IO 0.3–0.4pJ/bit与HBM系统2.5pJ+on-chip3pJ比较边界不同，也不是整机能效比。[[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=19|PDF p.19]]

### Push Mode到底公开了什么
材料公开的是传输分层、桥接模块和计算映射：片内NoC/封装D2D、卡和节点PCIe；JetStream图有segment address table、Corsair endpoint TLP address table、packer/unpacker、TOE、MAC仲裁；跨节点限定PP/EP，TP主要留节点内，跨rail由Push Mode通信。host-free DMA是数据路径主张，不等于CPU无需控制面参与。[[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=5|PDF p.5]] [[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=7|PDF p.7]] [[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=11|PDF p.11]] [[expo-hall-sessions/One-Abstraction-Many-Transports-Push-Mode-Communication-from-Chiplet-to-Rack-presented-by-d-Matrix.pdf#page=14|PDF p.14]]

没有公开具体操作码/API、地址注册与权限、credit/backpressure、发送/接收完成定义、fence/barrier、memory ordering、原子性/一致性、丢包重试或故障后幂等契约。因此“PCIe semantics over Ethernet”不能自行扩写成全局cache coherence，也不能假设一次Push即远端可见并可安全消费；应用graph完成语义仍须向厂商索证。

## 不确定性与待验证
应索取每种拆分的激活/KV大小、每token通信次数、批量/负载曲线、拥塞和故障重试、端到端ordering与隔离、真实功率及有效token成本。845tokens/s演示不能证明高并发p99，未来Raptor容量也不能填补当前2GB SRAM驻留限制。
