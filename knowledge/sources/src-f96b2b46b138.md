# SAI 观测闭环：平台约束查询与 SDK 边界 PerfMon

## 核心结论
先发现硬件允许的配置，再测量编程成本，能让控制器从“尝试并回滚”转为有约束的配置。但这测的是控制面 API，不是包转发时延或推理 p99。[[networking/02_Closing the Observability Loop in SAI From Performance Telemetry to Pl.pdf#page=3|PDF p.3]][[networking/02_Closing the Observability Loop in SAI From Performance Telemetry to Pl.pdf#page=11|PDF p.11]]

## 关键证据、指标与条件
- Constraints API #2294 在演讲时仍在 review；统一返回 MIN/MAX/STEP/DEFAULT/ALLOWED_VALUES，并接收对象实例、create-only 属性和 ingress/egress stage 等依赖，不能简化成一个全芯片固定上限。[[networking/02_Closing the Observability Loop in SAI From Performance Telemetry to Pl.pdf#page=6|PDF p.6]][[networking/02_Closing the Observability Loop in SAI From Performance Telemetry to Pl.pdf#page=7|PDF p.7]]
- HFT 报告间隔还受格式与 stat-id 共同影响：先创建未启用的对象图、查询/调参、最后 bind/start。启动时缓存于 STATE_DB 的示例只适合其已覆盖上下文；profile 改变后必须重新查询。[[networking/02_Closing the Observability Loop in SAI From Performance Telemetry to Pl.pdf#page=3|PDF p.3]][[networking/02_Closing the Observability Loop in SAI From Performance Telemetry to Pl.pdf#page=8|PDF p.8]][[networking/02_Closing the Observability Loop in SAI From Performance Telemetry to Pl.pdf#page=9|PDF p.9]]
- PerfMon #2287 已合入 SAI master，是新的对象类型；在 SDK 内计 CREATE/REMOVE/SET/GET/BULK 每对象延迟，排除调用方 IPC/排队。PERFDATA 是 u64，单位由 metric 决定，不能默认纳秒。[[networking/02_Closing the Observability Loop in SAI From Performance Telemetry to Pl.pdf#page=11|PDF p.11]]
- query-and-tune 示例明确说查询 API 本身能否被计时取决于 enum 覆盖，尚待确认。API 实现合入不等于每家 SDK 已支持。[[networking/02_Closing the Observability Loop in SAI From Performance Telemetry to Pl.pdf#page=12|PDF p.12]]

## 图表与架构
全文文字已读，未核验图像。架构为 discover→tune/apply→measure，并非声称存在已验证的 AI 自治控制器。

## 关联与比较

## 不确定性与待验证
没有实测 API 延迟、收敛时间、开销或跨厂商比较。需验证缓存失效、跨对象组合约束、原子性与变更期间的失效语义。SDK 计时之外的控制器排队、IPC、硬件生效时间仍须独立观测，不能由 PerfMon 独自承诺故障恢复 SLO。
