# AMC2.0：以强制profile收敛辅助设备的管理选择空间

> 阅读范围：已阅读本文件全部可提取文字（11页）。未完成图表视觉核对；不把文字提取视作图形关系验证。

## 核心结论

- AMC规范把MCTP/PLDM/SPDM众多可选项收敛为辅助设备管理要求；它把信息供给BMC，可在既有固件或interposer实现，明确不是BMC替代。[[systems-management/OCP-Auxiliary-Management-Controller-overview.pdf#page=2|PDF p.2]][[systems-management/OCP-Auxiliary-Management-Controller-overview.pdf#page=3|PDF p.3]]
- 2.0因新增/收紧mandatory要求而升主版本，不只是文件名更新。[[systems-management/OCP-Auxiliary-Management-Controller-overview.pdf#page=7|PDF p.7]]

## 关键证据

- 2.0定义更完整SPDM response/cert/firmware measurement要求，要求PLDM Type7 File I/O并规定依赖标准最低版本。[[systems-management/OCP-Auxiliary-Management-Controller-overview.pdf#page=8|PDF p.8]]
- 其他更新包括MCTP proxy、Type2 PDR/events、Type5更新命令、Type6 RDEOperationKill。[[systems-management/OCP-Auxiliary-Management-Controller-overview.pdf#page=9|PDF p.9]]
- smc-common为Zephyr参考库，含RDE/PLDM/MCTP/sensor/FRU/log/GPIO/watchdog基础设施；profile/Interop Validator作为功能互通验证工具。[[systems-management/OCP-Auxiliary-Management-Controller-overview.pdf#page=4|PDF p.4]][[systems-management/OCP-Auxiliary-Management-Controller-overview.pdf#page=5|PDF p.5]][[systems-management/OCP-Auxiliary-Management-Controller-overview.pdf#page=6|PDF p.6]]

## 指标与条件

无AMC面积/价格/功耗节省数字；2.0特性声明不等于每个采用smc-common产品全部合规。

## 图表与架构

无关键量化图；未视觉核对平台示意，仅用文字职责。

## 关联与比较

与CTAM不同对象但相同方法：协议支持声明不够，必须要求明确最低profile和可运行验收。

## 不确定性与待验证

需具体profile、命令时限、错误码和安全证书生命周期测试；能用RDE导出资源不等于设备故障恢复行为一致。
