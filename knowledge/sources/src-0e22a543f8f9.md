# DCC Introduction and State of the Art

## 核心结论
工作组将 data at rest/in transit/in use 分别对应 computational storage、DPU、PIM/PNM，重点从“做某个近数据硬件”转到 **可发现、可调用、可描述数据、可放置工作** 的完整软件契约。Paper 1 已发布、Paper 2 框架仍在草拟，是演讲时状态。[[fti-workshop-data-centric-computing/DCC-Introduction-and-State-of-the-Art.pdf#page=2|PDF p.2]] [[fti-workshop-data-centric-computing/DCC-Introduction-and-State-of-the-Art.pdf#page=6|PDF p.6]]

## 关键证据
- 栈层次：AI framework→compiler/runtime→control/data API→formats/transforms→设备；必须描述 load/store 或 queued command、source/sink、coherence、函数与 layout。[[fti-workshop-data-centric-computing/DCC-Introduction-and-State-of-the-Art.pdf#page=6|PDF p.6]]
- Arrow 用 offset-based 可重定位布局，HDF5 提供对象/chunk 及服务器侧执行接点，ONNX 描述模型，Substrait/Arrow compute 描述计算语义；格式互通不等于所有设备都无需转换。[[fti-workshop-data-centric-computing/DCC-Introduction-and-State-of-the-Art.pdf#page=7|PDF p.7]]
- 以 SNIA CS API v1.1 的 discover→activate→allocate→move→execute→complete 复用为起点，仍需扩展 device class、按 NUMA/CXL/flow 发现、stream source/sink、mappability/coherence、dtype/shape/stride/layout、function registry 和 placement hints。[[fti-workshop-data-centric-computing/DCC-Introduction-and-State-of-the-Art.pdf#page=8|PDF p.8]]
- Device-first 先暴露 memory、accelerator 在其后；accelerator-first 先暴露 accelerator、memory 在其后；框架需容纳两者及混合，不应预设单一拓扑。[[fti-workshop-data-centric-computing/DCC-Introduction-and-State-of-the-Art.pdf#page=9|PDF p.9]]

## 指标与条件
p.4 汇集不同论文/工作负载的 PIM/PNM/CS/DPU 性能和能耗数值。它们不是同机同任务横向实验，**不用于给四种设备排性能优劣**。[[fti-workshop-data-centric-computing/DCC-Introduction-and-State-of-the-Art.pdf#page=4|PDF p.4]] 本讲无统一端到端量化基准。

## 图表与架构
p.10 明确区分已跑通的 NDC reference、ExecuTorch GEMV、FAISS IVFFlat、plugin 与尚开放的 coherence、stream、registry、placement、cluster partition、management/security。[[fti-workshop-data-centric-computing/DCC-Introduction-and-State-of-the-Art.pdf#page=10|PDF p.10]] p.12/13 是 GPU dense compute、CXL shared KV、PNM retrieval、DPU/storage preprocessing 的目标架构/路线图，不是已验证的完整开放集群。[[fti-workshop-data-centric-computing/DCC-Introduction-and-State-of-the-Art.pdf#page=12|PDF p.12]] [[fti-workshop-data-centric-computing/DCC-Introduction-and-State-of-the-Art.pdf#page=13|PDF p.13]]

## 关联与比较
作为 [[knowledge/concepts/compute-memory-ndp-contract|近数据卸载契约]] 的框架入口；结合具体集成经验再判断每一层是否已有实现，不能用一张全栈架构图替代兼容性证据。

## 不确定性与待验证
演讲给标准版本/发布状态仅是 2026 会议快照。仍未解决由应用、compiler 还是 runtime 决定 placement；也未证明大规模多租户 SLO 或统一安全模型。
