# XPU Scale Composable Smart Memory Fabric

## 核心结论
Marvell把memory fabric定位为 **KV data service的执行位置**，不仅是远端字节仓库：lookup/hash/metadata/serde、policy、compression可从host移到near-memory Arm核，数据面采用PCIe P2P DMA。产品规格、early inference benchmark、compression实验和Nixlbench必须分开解读。

## 关键证据
- p.9 shared KV service实现store once/read multiple，compute与cache独立扩展；API分data management、storage management、KV optimization和transport。架构主张不等于所有功能均已成熟/测量。[[Server：Composable Memory Systems/XPU Scale Composable Smart Memory Fabric.pdf#page=9|PDF p.9]]
- p.14明确GPU-facing路径是 **PCIe P2P DMA，GPU端不需要CXL**；expander DMA发起对HBM访问，GPU被动；数据不经host DRAM。不能把这叫GPU原生CXL.mem load/store。[[Server：Composable Memory Systems/XPU Scale Composable Smart Memory Fabric.pdf#page=14|PDF p.14]]
- p.15写路径由GPU DMA/DAX plugin push，读路径由Structera ODM plugin push，示例连续KV block为2MB；控制平面与data plane分离。[[Server：Composable Memory Systems/XPU Scale Composable Smart Memory Fabric.pdf#page=15|PDF p.15]]

## 指标与条件
### KV-service early结果（p.10）
Llama3.1-8B/H200、lmbench long-docQA、peak users16。输入吞吐与mean TTFT分别：recompute31394input tok/s /5933ms；SSD44318/4243；CPU-load DRAM80813/2162；Structera139497/1199。讲者“4× throughput、5× TTFT”基线是recompute；相对DRAM约1.73×吞吐、44.5%较低mean TTFT（本库算术）。**input tokens/s不是decode输出tokens/s，mean不是p99。** [[Server：Composable Memory Systems/XPU Scale Composable Smart Memory Fabric.pdf#page=10|PDF p.10]]

### Compression独立实验（p.12）
Llama3.1-8B-Instruct BF16、4×64K documents×10rounds、tile shuffle、4 inflight；H200 memory_util27%、StructeraA32+32GB，G2.5 6GB、compressed G3 12GB。raw/FP8/TurboQuant k8v4/CacheGen mean TTFT 4864/3374/2914/2834ms，input tok/s16832/22860/22845/25594；平均Arm cores0.5/2/7.4/0.6。CacheGen标注**implementation incomplete**。所谓accuracy loss为cosine similarity angle，0/1.52/3.9/13.4度，不是任务准确率下降百分比。表中occupied bytes与compression ratio不能直接互除，可能受不同驻留/命中影响；不能用278MB对8000MB推导“28.8×压缩”。[[Server：Composable Memory Systems/XPU Scale Composable Smart Memory Fabric.pdf#page=11|PDF p.11]] [[Server：Composable Memory Systems/XPU Scale Composable Smart Memory Fabric.pdf#page=12|PDF p.12]]

### Nixlbench（p.16–17）
扫4KB–64MB块；64MB端点read bandwidth50.6 vs46.3GB/s、write55.5 vs46.3GB/s（Structera vs RDMA）；latency同端点1325 vs23199µs读、1209 vs23197µs写。**吞吐与latency曲线差距不能仅凭图直接视为同队深同批次单次链路延迟**，需要原始benchmark配置解释。[[Server：Composable Memory Systems/XPU Scale Composable Smart Memory Fabric.pdf#page=16|PDF p.16]] [[Server：Composable Memory Systems/XPU Scale Composable Smart Memory Fabric.pdf#page=17|PDF p.17]]

### 规格/路线信息，不是上述实验的硬件配置
PFMA页宣称1TB HBM3e+16/32TB DDR5、16compute nodes/XPUs、CXL3.1 DCD、访问<350ns；Structera S页宣称2TB/s switch capacity、port-to-port<100ns、135W、up to100TB pool。没有给对应多租户满载实测与延迟分布；不同起止点的ns不能与KV服务µs/ms相比较。[[Server：Composable Memory Systems/XPU Scale Composable Smart Memory Fabric.pdf#page=4|PDF p.4]] [[Server：Composable Memory Systems/XPU Scale Composable Smart Memory Fabric.pdf#page=5|PDF p.5]]

## 图表与架构
已检查上述所有关键页。附录p.20/21早期配置为24GB KV、约3×64K文档×20queries、4 inflight、32GiB共享DAX窗口、vLLM0.22、512token chunk、GPU memory_util0.26、关闭vLLM自身prefix cache；**与p.10 peak users16及p.12独立compression配置不完全相同**，不强行合并成一个实验。[[Server：Composable Memory Systems/XPU Scale Composable Smart Memory Fabric.pdf#page=20|PDF p.20]] [[Server：Composable Memory Systems/XPU Scale Composable Smart Memory Fabric.pdf#page=21|PDF p.21]]

## 不确定性与待验证
需区分GPU memory读取、control/service处理、bulk transfer和完整请求的latency测量边界；补充RDMA基线拓扑/queue depth、CPU核预算、任务质量、精度、p99、cost/energy。p.18 stable API/open object format属于合作探索方向，不应描述为所有framework已统一接口。
