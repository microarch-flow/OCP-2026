# 01_AI Computing Continuum Use Cases and Collaboration Items

## 核心结论
NTT/Red Hat/1Finity把跨域工作负载分成Reach-Across远程读取、Sync-Across复制和Scale-Across分布式计算。它们对距离敏感性不同，不能用“光网络近本地性能”一个结论覆盖全部。[[ai-computing-continuum/01_AI Computing Continuum Use Cases and Collaboration Items.pdf#page=2|PDF p.2]] [[ai-computing-continuum/01_AI Computing Continuum Use Cases and Collaboration Items.pdf#page=17|PDF p.17]]

## 关键证据
Reach-Across PoC：Unet3D、MLPerf Storage v1.0.1、28000图像约3.8TB、4×H100；存储与GPU分处两站，100G APN实际40km、最高500km仿真，NFS over TCP/RDMA，同站存储/GPU为基线。pipeline在计算batch N时加载N+1，隐藏延迟要求每batch加载时间≤计算时间且持续带宽足够。[[ai-computing-continuum/01_AI Computing Continuum Use Cases and Collaboration Items.pdf#page=4|PDF p.4]] [[ai-computing-continuum/01_AI Computing Continuum Use Cases and Collaboration Items.pdf#page=5|PDF p.5]]

## 指标与条件
40km epoch357→364s，约+1.9%；100km throughput保留94%至9.66GiB/s，NFS nconnect=16。不能外推同步collective或每token关键路径。PUE1.56对1.98抵消约20% IT energy增加是作者总能耗近持平解释，但页内混用power/energy，未给完整电表边界和时间窗。[[ai-computing-continuum/01_AI Computing Continuum Use Cases and Collaboration Items.pdf#page=6|PDF p.6]]
另一个约100G optical endpoint原型在180km保持约90–93Gbps，图包含8k/512k消息；它不是上述Unet3D同一实验，也不是统一应用tail-latency证明。[[ai-computing-continuum/01_AI Computing Continuum Use Cases and Collaboration Items.pdf#page=19|PDF p.19]]

## 图表与架构
已看setup、pipeline、结果、PD架构与endpoint曲线。p.15的llm-d/vLLM/LMCache/NIXL、GPU/CPU+CXL/storage三级KV和CoHDI/Redfish资源编排是跨域PD PoC结构，未给模型/TTFT/TPOT成绩。[[ai-computing-continuum/01_AI Computing Continuum Use Cases and Collaboration Items.pdf#page=15|PDF p.15]]

## 不确定性与待验证
p.6“数据不离开站点”应限于不预复制持久数据集；远端GPU按需读数据并不证明数据未传输/未在远端处理。需信任边界、加密、远端内存保留与隔离证据，不能仅凭该口号声称zero-trust或合规。p.11金融FC-SAN/DB同步分阶段计划同样不是已实现全部收益。[[ai-computing-continuum/01_AI Computing Continuum Use Cases and Collaboration Items.pdf#page=6|PDF p.6]] [[ai-computing-continuum/01_AI Computing Continuum Use Cases and Collaboration Items.pdf#page=11|PDF p.11]]
