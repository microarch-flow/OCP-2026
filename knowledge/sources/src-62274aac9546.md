# FADU AI上下文存储：减少数据通路与谨慎取消冗余

## 核心结论
本讲把上下文缓存与持久主副本分开，提出以集成NIC的DPU直接连接SSD，减少CPU、PCIe switch与DRAM拷贝。价值取决于命中/重算代价和故障后SLO，而不是“缓存可重算，所以不需要任何韧性”的普遍规则。[[expo-hall-sessions/The-Changing-Course-of-Storage-in-an-AI-World-presented-by-FADU.pdf#page=9|PDF p.9]] [[expo-hall-sessions/The-Changing-Course-of-Storage-in-an-AI-World-presented-by-FADU.pdf#page=10|PDF p.10]] [[expo-hall-sessions/The-Changing-Course-of-Storage-in-an-AI-World-presented-by-FADU.pdf#page=11|PDF p.11]]

## 关键证据、指标与条件
- 旧架构示例为双24core CPU、128–384GB DRAM、100Gb NIC、24×8TB U.2/192TB raw、约600W SSD功率；NUMA、memcopy、双端口/RAID是讨论瓶颈，不是对所有PCIe4系统的实测结论。[[expo-hall-sessions/The-Changing-Course-of-Storage-in-an-AI-World-presented-by-FADU.pdf#page=3|PDF p.3]]
- 推理存储需求表给>1TB/s、>1PB和高并发，明确需集群；这是目标需求，不是单机吞吐。其“resiliency低”只适用于非唯一数据副本的cache类负载。[[expo-hall-sessions/The-Changing-Course-of-Storage-in-an-AI-World-presented-by-FADU.pdf#page=5|PDF p.5]]
- “Possible Future”架构：每blade 32core DPU约125W、64GB DRAM、400/800Gb RoCE、12×16TB以上E3.S约1DWPD，无独立NIC/PCIe switch；1/2U多个blade，按需扩盘。没有实物吞吐/功耗验证，不能把图上1200W PSU当墙插耗电。[[expo-hall-sessions/The-Changing-Course-of-Storage-in-an-AI-World-presented-by-FADU.pdf#page=10|PDF p.10]]
- 800Gbps即理论100GB/s线速、未扣协议开销，单口不能供给前述>1TB/s集群需求；所需端口数还取决于读写方向、并发与容错（单位换算/本库归纳）。[[expo-hall-sessions/The-Changing-Course-of-Storage-in-an-AI-World-presented-by-FADU.pdf#page=5|PDF p.5]] [[expo-hall-sessions/The-Changing-Course-of-Storage-in-an-AI-World-presented-by-FADU.pdf#page=10|PDF p.10]]
- 原文建议避免RAID/EC、以usableGB/year算TCO，同时也提EC可提供HA但需足够节点；这是可选策略，不是内容相互证明。建议把容量成本补成满足SLO的缓存服务成本。[[expo-hall-sessions/The-Changing-Course-of-Storage-in-an-AI-World-presented-by-FADU.pdf#page=10|PDF p.10]] [[expo-hall-sessions/The-Changing-Course-of-Storage-in-an-AI-World-presented-by-FADU.pdf#page=11|PDF p.11]]
