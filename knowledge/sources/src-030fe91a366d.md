# Scale-up Pod安全：组合与租约是保证单位

> 阅读范围：已阅读本文件全部可提取文字（14页）。关键页已视觉核对：11；不代表逐页视觉审核。

## 核心结论

- 作者主张动态组合系统中端点证明+加密链路必要但可能不足：当fabric状态可破坏安全性质时，设备成员、partition、路由/地址映射也必须进入证明。[[Security/From Securing Links to Securing Pods- Security of Scale-Up Networks.pdf#page=5|PDF p.5]][[Security/From Securing Links to Securing Pods- Security of Scale-Up Networks.pdf#page=6|PDF p.6]]
- 保证对象从单设备/链路扩展为pod composition，但作者明确是有条件、协议无关论点，不是宣称每种fabric都必须相同TCB。[[Security/From Securing Links to Securing Pods- Security of Scale-Up Networks.pdf#page=4|PDF p.4]][[Security/From Securing Links to Securing Pods- Security of Scale-Up Networks.pdf#page=6|PDF p.6]]

## 关键证据

- Management负责设备身份/固件/库存/恢复；control/config负责partition、路由、keys、QoS和生命周期授权；data plane负责机密性、完整性、顺序和隔离。[[Security/From Securing Links to Securing Pods- Security of Scale-Up Networks.pdf#page=7|PDF p.7]][[Security/From Securing Links to Securing Pods- Security of Scale-Up Networks.pdf#page=8|PDF p.8]][[Security/From Securing Links to Securing Pods- Security of Scale-Up Networks.pdf#page=9|PDF p.9]]
- Admission是条件租约：形成→验证准入→监控假设→恢复重取证→清理重分配→撤授权销钥；假设变化可run/restrict/revoke。[[Security/From Securing Links to Securing Pods- Security of Scale-Up Networks.pdf#page=11|PDF p.11]]
- 每个声明需明确性质、依赖状态、机制终止点和谁签何种证据。[[Security/From Securing Links to Securing Pods- Security of Scale-Up Networks.pdf#page=10|PDF p.10]]

## 指标与条件

8 XPU与拆成2×4是组成示例，不是吞吐/隔离benchmark；无重配置延迟、证明窗口或tenant性能隔离数据。[[Security/From Securing Links to Securing Pods- Security of Scale-Up Networks.pdf#page=5|PDF p.5]]

## 图表与架构

已视觉核对p.11生命周期与run/restrict/revoke结果，未把租约理解为一次性启动白名单。

## 关联与比较

与Composite Attestation相接：后者绑定设备集合，此材料要求继续覆盖fabric配置和运营状态；与hitless更新共同指向“变化后安全仍成立”的证据。

## 不确定性与待验证

缺具体协议的可测量状态、原子重配置、残留数据清理、故障重训/路径切换时的授权一致性实现。
