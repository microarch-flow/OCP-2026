# Bringing General-Purpose Parallel Programming to Near-Data Compute

## 核心结论
PXL 的卖点不是固定功能 offload，而是 C++/Rust 单源编程、共享虚拟地址映射及可分配的独立线程子系统。真正需要建模的仍是地址翻译、一致性发布、任务调度和 CPU/device 通信。[[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=8|PDF p.8]] [[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=11|PDF p.11]] [[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=13|PDF p.13]] [[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=16|PDF p.16]]

## 关键证据
- MX1P 规格页：3,072 RISC-V MU cores、24 subsystems、FP32/FP16；4 通道 DDR5-8400、最多 2 TB；CXL 3.2 Type3/PCIe6。p.4 的连线又标 CXL3.0，并区分 MX1P PoC x8 CXL+x8 PCIe 与 MX1 production 2×x8 CXL+2×x4 PCIe，属于不同状态，不能合并成已交付配置。[[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=3|PDF p.3]] [[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=4|PDF p.4]]
- CXL-aware allocator 记录 V2P 并配置 device MMU，设备解析 host user VA；“同一指针”依赖映射与生命周期契约，不是通用任意指针免设置。[[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=8|PDF p.8]]
- HDM-H 放较稳定 vectors/embeddings，设备 flush 发布；HDM-DB 放可变 index/hash，由 back-invalidation 保持 host cache 一致。flush 成本与 BI 流量是设计权衡。[[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=11|PDF p.11]]
- 每 subsystem 128 独立状态线程，不是 lockstep warp；job 可占多 subsystem、跨 tenant 分配。并发可隐藏等待，但不能创造物理链路带宽。[[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=13|PDF p.13]]
- 控制面仍用 SQ/doorbell、DMA 传 binary/args、CQ completion；“就地计算”不等于系统完全没有复制。[[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=15|PDF p.15]]

## 指标与条件
p.21 对比 Intel GNR 6767P sub-NUMA 32 cores/4 memory channels。**4.81× Flat、1.99× IVF-Flat、1.92× IVF-RaBitQ、1.65× HNSW 是两台 MX1P 的柱顶数值，不是单设备。** 单设备 IVF/HNSW 柱约等于或低于 CPU，不能忽略设备数及资源差异。作者声称线性扩展，图只显示 1/2 devices，不能外推大规模。数据集、维度、recall、功耗未完整披露。[[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=21|PDF p.21]]

## 图表与架构
PXCC 从单一 C++/Rust 源生成 host + MU binary 并打包；SDK 有 compiler/runtime/debugger/profiler/QEMU。[[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=16|PDF p.16]] [[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=18|PDF p.18]] 分层 HNSW 在 host 保留上层、device 执行下层；scatter-gather 改为近端 gather 后顺序读取，减少小写入占满 cache line 的放大。[[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=9|PDF p.9]] [[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=20|PDF p.20]]

## 关联与比较

## 不确定性与待验证
XFLARE/Spark→Gluten/Velox→Substrait/Arrow 的 SQL operator 下推标为 development，不能当成熟 benchmark。[[fti-workshop-data-centric-computing/Bringing-General-Purpose-Parallel-Programming-to-Near-Data-Processing.pdf#page=22|PDF p.22]] 需测 page fault、映射失效、动态对象回收、租户隔离，以及一/二设备等功耗资源归一化结果。
