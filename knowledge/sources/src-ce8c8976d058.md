# 带外无影响微码更新：先分发、后所有者授权、再多插槽协调激活

> 阅读范围：已阅读本文件全部可提取文字（15页）。关键页已视觉核对：12, 14；不代表逐页视觉审核。

## 核心结论

- 方案将payload、manifest、eligibility metadata装入同一PLDM包；BMC先向所有目标socket staging，Owner在激活前授权，最后平台级rendezvous协调激活。[[Security/Out of Band Seamless Updates with Runtime Authorization.pdf#page=3|PDF p.3]][[Security/Out of Band Seamless Updates with Runtime Authorization.pdf#page=11|PDF p.11]]
- OOB是传输/编排路径，不自动等于impactless；能否在线安全激活由版本、Impact、TCBR等eligibility与芯片硬件条件共同决定。[[Security/Out of Band Seamless Updates with Runtime Authorization.pdf#page=12|PDF p.12]]
- 分工保持运营方负责时间、guardrail/rollback，芯片方负责正确性与硬件安全激活。[[Security/Out of Band Seamless Updates with Runtime Authorization.pdf#page=7|PDF p.7]]

## 关键证据

- Security Engine检查manifest、许可MCU hash/SVN；Manageability FW流式处理，不能缓冲全部payload；未经授权按损坏包拒绝、不触发uCode。[[Security/Out of Band Seamless Updates with Runtime Authorization.pdf#page=5|PDF p.5]][[Security/Out of Band Seamless Updates with Runtime Authorization.pdf#page=6|PDF p.6]]
- 所有目标socket完整staged之后才激活；每socket独立请求但一次平台级同步。冲突活动可拒绝，PLDM返回错误后代理稍后重试。[[Security/Out of Band Seamless Updates with Runtime Authorization.pdf#page=11|PDF p.11]][[Security/Out of Band Seamless Updates with Runtime Authorization.pdf#page=14|PDF p.14]]
- p.12绿色有效无影响组合是Minimum Runtime Revision不高于current、Impact=0、TCBR=0；Impact=0而TCBR=1标为invalid，其他行含instability risk。[[Security/Out of Band Seamless Updates with Runtime Authorization.pdf#page=12|PDF p.12]]

## 指标与条件

没有暂停时长、core stall、p99延迟、并发租户影响或更新成功率数字；“impactless”是满足资格的方案目标，非本文件实测SLA。MCU在这里指microcode update而非微控制器。[[Security/Out of Band Seamless Updates with Runtime Authorization.pdf#page=15|PDF p.15]]

## 不确定性与待验证

需补部分socket失败回滚、一致版本可见性、异构微码依赖、TCB恢复策略与SLO窗口实测。统一eligibility契约与PLDM错误码仍是征集标准化的事项。[[Security/Out of Band Seamless Updates with Runtime Authorization.pdf#page=7|PDF p.7]]
