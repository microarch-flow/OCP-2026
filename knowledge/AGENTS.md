# 知识库维护约定

## 目标与边界

本仓库整体是 Obsidian vault。现有 PDF 与目录是不可变原始层；只在 `knowledge/` 中增加衍生内容，不移动、不改名、不覆盖原始资料。不要把文件名、文字提取成功或模型生成等同于已阅读或已验证。所有实质分析以中文撰写，保留必要英文术语。机器提取的完整文本仅留在本地处理目录，不写入公开知识库；交付内容是独立撰写的分析、必要短引文、元数据与维护脚本，不复制全文。

`OCP-2026` 是仓库/语料集名称，不是所有演讲举办年份的证据。会议名称、年份和日期只按各来源实际陈述记录；若写明 2025 或未给日期，不根据仓库名称改成 2026。

本结构借鉴 [Andrej Karpathy 的 LLM Wiki 原始说明](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)：原始资料、互链 Markdown、维护规则三层，以及 ingest / query / lint。具体 ID、证据规范与目录是本仓库的适配，不是原文规定。

## 身份与版本

- `id = "src-" + sha256(原始仓库相对路径的 UTF-8 字节).hexdigest()[:12]`。不做 Unicode 规范化、不排序编号、不以标题猜测路径。该 hash 是**路径身份**，不是文件内容 hash。
- 源卡固定为 `knowledge/sources/<id>.md`。重名标题通过 ID 区分；同一内容出现在不同路径时仍保留两条来源。
- `source_git_blob_sha` 使用 Git tree 中的 blob SHA；`source_commit` 是该来源快照。不能将 blob SHA 或路径 hash 伪装成 SHA-256 内容校验和。
- 原始路径改变时新增身份，并注明旧路径；内容 SHA 改变时重读来源、标记依赖分析待复核，不静默继承旧分析状态。
- 页数只从实际 PDF/提取结果读取，未知写 `null`。原始大小为 0 的文件标记 `blocked-empty`，不能从标题写摘要。

## 源卡最低标准

复制 `templates/source-card.md`，填写真实字段后才能进入 `sources/`。模板不是已分析来源，不要批量生成空源卡。

扁平 YAML 字段：`id`, `type: source`, `title`, `source_path`, `source_git_blob_sha`, `source_commit`, `source_pages`, `review_status`, `evidence_pages`, `tags`。`concepts` 中的 wikilink 必须加引号。推荐字符串双引号、数组使用 JSON 兼容行内格式，便于无依赖脚本读取。允许 `text_reviewed`, `key_pages_visual_checked`, `updated` 等额外可审计字段。

`review_status` 允许：

| 状态 | 精确定义 |
| --- | --- |
| `pending` | 未形成实质分析；只出现在清单中，不创建空源卡 |
| `partial` | 已读部分内容，明确范围及未读部分，不计入已分析完成数 |
| `analyzed-text` | 已阅读可提取文字并完成有页级证据的分析；没有声称图表已核对 |
| `analyzed-visual` | 满足文字分析条件，且关键引用图表/架构/指标所在页已做视觉核对；列出 `key_pages_visual_checked`，并不意味着逐页视觉审核 |
| `blocked` | 原始文件为空、无法取得或损坏，记录具体原因，不生成替代性内容 |

正文应包括：`核心结论`、`关键证据`、`指标与条件`、`图表与架构`、`关联与比较`、`不确定性与待验证`。可以增加标题页信息、适用场景、实践建议等，不要为不存在的指标强行填数。

1. **原始陈述**：明确“该演讲/作者/厂商声称”；有出处不等于独立证实。
2. **跨源归纳**：明确是我们的综合判断，列出支持它的源卡及各自原始页。
3. **尚待验证**：缺失基线、测试条件、统计量、图表细节或外部证据时直说。
4. 每条重要结论给物理 PDF 页码，示例语法为 `[[原始目录/实际文件.pdf#page=3|PDF p.3]]`。若页脚标号不同，附注页脚号；`evidence_pages` 列出引用的物理页。
5. 定量指标必须记录数值、单位、对象、基线、工作负载/测试条件、出处页；缺失项标“未给出”。不能将峰值/预测值/实验值/量产结果混在一起。
6. 重要图表要看实际渲染页，不能仅凭提取文字恢复箭头、坐标或空间关系。纯文字分析需披露此局限。
7. panel、封面、议程、简报不等于完整演讲或录音；仅分析文件实际包含的信息。

## 跨源知识

- `concepts/`：定义 → 来源与页级证据 → 共识/分歧 → 适用条件 → 未决问题。只建立被实际分析支撑的概念，不根据目录猜测结论。
- `comparisons/`：先定义比较问题、口径、条件，再给并列证据与冲突。不可比较的数据保持不可比较。
- `topics/`：主题入口、阅读路线、来源目录。自动目录区以外可补人工/分析正文；不要覆盖用户修改。
- `questions/`：明确尚未解决的具体问题及下一份证据需求。不要用问句掩饰未经支持的结论。
- 不把同一厂商数据的多次转述当作多个独立证据。

## Obsidian 与链接

- 从**整个仓库根目录**打开 vault，不是只打开 `knowledge/`。笔记使用完整仓库路径 wikilink，如 `[[knowledge/index]]`；附件保留扩展名，页嵌入形如 `![[实际路径.pdf#page=3]]`。
- 路径中的中文、全角冒号与空格原样保留。当前快照没有 `#`, `^`, `|`, `[` 或 `]` 等歧义字符；新增文件若有这些字符，先验证链接行为，不擅自改原文件名。
- Markdown 表格内显示别名分隔符需要转义：`\|`。属性中的 wikilink 加引号。
- 不创建指向尚不存在的源卡/概念的假链接；未分析来源链接到原始 PDF，并显示“待分析”。
- 自动检查可验证路径存在和页码范围，不能代替 Obsidian 实机渲染测试。

## 更新、查询与验收

1. **Ingest**：核对来源快照；提取文本与页数；阅读并对必要页面做视觉核对；写源卡；再维护概念/比较页。
2. **Query**：先检索已有源卡，回查 PDF 页。值得保留的新回答写入概念/比较/问题页，不把模型回答作为独立来源。
3. **Refresh**：运行 `python knowledge/scripts/refresh.py`。本地有提取日志时可加 `--extraction-log /实际路径/extraction-log.jsonl`。脚本仅覆盖标记为 GENERATED 的区域与机器清单，不写源卡，不把 extracted 晋升为 analyzed。
4. **Lint**：运行 `python knowledge/scripts/validate.py`。它检查 ID、版本、源卡证据字段、页范围、wikilink、空来源错误分析、统计一致性等；它不判断语义正确性，也不宣称视觉验证。
5. **Source integrity**：完整仓库可运行 `python knowledge/scripts/validate.py --check-source-bytes`，逐一核对原 PDF 字节数和 Git blob SHA。没有原文件的组装工作区只做 manifest-backed 链接验证，并明确区分未运行的字节检查。
6. 每次重要输入/分析/检查/发布以新条目**追加**到 `log.md`；不改旧条目来制造进度。保留用户编辑；冲突要显式处理。
7. 发布前刷新清单、运行检查、核对未读与不可读数量。只在实际已分析的范围内报告完成度；不把 501 项清单称为 501 篇分析。
